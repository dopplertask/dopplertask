# Connectors

A connector is a service that steps can work with, described in one file in `backend/src/main/resources/connectors/`. Each connector is one step in the editor, such as Slack, with its actions to choose from, and its triggers start a task, each from a start tile of its own when the task has several. The format is documented in `Connector.kt`, and `ConnectorFormatTest` shows every word in use.

## What a file holds

* **name, label, description, icon** and **upstream**, the package and version it was copied from.
* **hosts**: the only hosts a request with the connector's credential may go to. A host may name a credential value, such as `{{credential.subdomain}}.zendesk.com`, and an input never decides a host.
* **baseUrl**: where the API starts. With it, every connector also offers a **Custom API call**.
* **credential**: its fields, and where they go: `headers`, `query`, `body`, `basic`, or `oauth2` to sign in with an account. A `session` signs in first for a short-lived token, such as with a user name and password, or for a page's own token with the step's `{{page}}`; the step's requests and its scripts' calls then carry only the token, by `{{session}}` in the session's `headers` or `query`, while its lists and the sign-in itself are signed with the credential. A session is used only when the credential has every value its request needs.
* **actions**, each with its `inputs`, its `request` (`method`, `url`, `headers`, `query`, `body`), and what it gives: `result`, `outputs`, or `download` for an answer that is a file. An action with `resume` waits, such as for an approval: its request and scripts get `{{resumeUrl}}`, the one-time address of the run, and the run stops after the step with the status waiting. When the address is called, also as a link opened in a browser, the step runs again without its request: `resume` reads what arrived as `response` and its headers, query and text as `received`, without the cookie and authorization of the person who answers, and returns what the step gives. `{{resumeUrl}}/confirm` is a page with Approve and Disapprove buttons, for a link in an email: opening it, as a mail scanner does, answers nothing, and a button answers with `action=approve` or `action=disapprove` in the query. A fixture's `answer` (`body`, `headers`, `query`) is what arrived, and the recorder runs the original a second time with it.
* **triggers**, which ask the service every few minutes for what is new (`newBy` time, lastItem, or unseen for a list in no order; a time may be a number of seconds or milliseconds, ISO 8601 with or without a colon in its offset, RFC 2822, a date and time without a zone, read as UTC, a date alone, or `/Date(milliseconds)/`), or take its events with `webhook`. A check may ask only for what came after its place, with `{{lastPollTime}}` for a check by time or `{{lastItem}}` for one by last item, and `emit` gives the part of each listed entry that is the item, such as `$.data` when the entry holds its time beside it. A trigger's scripts also have `memory`, an object kept from one check or event to the next, such as the cursor a service gives; it holds what the original keeps in its store, by the same names, and the check compares it with the store the original left. A webhook with a `subscribe` request sets itself up, and `renewEvery` subscribes it again after that many hours when the service ends subscriptions, such as a Google Drive channel; one without shows the person an address to copy into the service. A service that sends the events of a whole app to one address, such as Slack, has the connector's `events`: the person sets `/hooks/app/<connector>` once in their app, `reply` answers its challenge, `event` and `identifier` give each event's kind and account, and `signature` says how the service signs it; a trigger with `"app": true` takes the `events` kinds it lists, for the account its `subscribe` request finds by `id`. A `signature` (`header`, `algorithm`, `key` from the credential, signed `text` from `{{text}}`, `{{headers.name}}` and `{{query.name}}`, `encoding` hex or base64, `prefix`, and `signedAt`, when the service signed the event in seconds, such as `{{headers.x-slack-request-timestamp}}`) refuses an event that someone else made, and with `signedAt` one without that time or signed more than five minutes before or after it arrived, so that a captured event cannot be sent again; any webhook can have one. A fixture signs its event's text as compact JSON, and its event arrives when it was signed. Events arrive at `/hooks/<key>` as JSON, a form (read as nested fields, such as `contact[email]`) or text, and `reply` sets what the address answers, as JSON or text, such as a challenge the service sends back to check it; what it answers is a check, not an event, and it reads memory without changing it. Scripts read an event as `response` and what came with it as `received`: its headers, query and text, and `at`, when it arrived in seconds.

## Inputs

`string`, `multiline`, `number`, `boolean`, `select`, `json` and `file`. A `file` input names a file the run keeps, such as one Read file read. It is sent as base64 in JSON, as a part of a multipart body (parts come in the body's order; `multipart/related` types each part), or as the whole body when the body is only that file. A body that is text is sent as that text in any type but JSON, such as `text/csv`, or a form that a script wrote; a form body with fields is sent as its fields. An answer that is not JSON reaches scripts as text, an empty one as null, and `received` gives its status, headers and text. A script can keep a file it finds, such as an attachment sent as base64, with `keepFile(name, base64)`, which gives the name of the run's file, made unique when another file or value of the run has it; a trigger's files go with the item that names them into the run it starts. `readEmail(raw)` reads an email, as text or base64url as Gmail gives it, into the fields mailparser gives, with each attachment's bytes as base64. `list` names one of the connector's `lists`, so that a person chooses the value from the service, such as a table of a base. A list is written once and shared by every input that names it, and its request can use the inputs of the action it is chosen in: the editor reads it again when one of them changes, and asks for them first when they are empty. A typed value or one from an earlier step still works, so agents send the ID itself. `fieldsFrom` gives an input a form whose fields come from the service, such as the columns of a table.

## Logic

`beforeRequest` and `afterResponse` are short JavaScript functions of `inputs`, `request` and `response`. They run with no way into Java, files or the network, and never see the credential: a secret credential value in an address, such as a bot token in `baseUrl`, shows as its name, `{{credential.botSecret}}`, and only the part of the address the script was given, also in a `call()`, gets the value back; a `call()` to a path such as `/getMe` gets the connector's base with its value, as every request does. Nothing a script adds gets a credential, and no message about a request shows a secret. A secret value may stand in a path only in `baseUrl`, and never in a host. `call({method, url, query, headers, body})` sends another request through the connector, such as for the next page.

## Proving a connector

Every action and trigger has a fixture in `backend/src/test/resources/connector-fixtures/<connector>/`. `tools/connector-harness/record.mjs` runs the original with the fixture's inputs and records what it sends, without leaving the machine, and `ConnectorCheck` runs ours with the same inputs and compares:

```bash
cd tools/connector-harness && node record.mjs ../../backend/src/test/resources/connector-fixtures/resend/get_contact.json
cd backend && ./gradlew connectorCheckClasspath && java -cp "$(cat build/connector-check-classpath.txt)" com.dopplertask.dopplertask.ConnectorCheck resend
```

The recorder needs Node 22 or later. The recorder and the check both run in UTC, so that a time is written the same on every machine. The check reads the files from the source folders, so a new or changed connector needs no build.
